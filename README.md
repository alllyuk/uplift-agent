# Uplift Agent

Агент для построения решений по клиентским интервенциям в банке. Помогает оценить, стоит ли применять конкретную интервенцию к клиенту, и объясняет ожидаемый эффект на основе нескольких внутренних источников и аналитических инструментов.

## Что за задача

Во многих компаниях решение о том, какую интервенцию предложить клиенту, принимается вручную: аналитик или менеджер смотрит профиль клиента, историю взаимодействий, внутренние рекомендации, внешние факторы и пытается понять, будет ли действие полезным.

Это долго, дорого и плохо масштабируется. Данные разрознены, интерпретации могут отличаться от эксперта к эксперту, а качественная причинно-следственная оценка требует отдельной аналитической работы.

## Для кого

- CRM / retention / marketing teams
- account managers / customer success
- бизнес-аналитики
- руководители, которым нужны объяснимые рекомендации

## Какая боль сейчас

- контекст о клиенте лежит в нескольких системах;
- для оценки интервенции нужно вручную собирать данные;
- причинно-следственный анализ требует экспертизы и времени;
- решения слабо воспроизводимы;
- часть интервенций делается без достаточного обоснования.

## Что делает Proof of Concept

PoC принимает кейс по клиенту и работает в одном режиме:

**Оценка конкретной заданной интервенции**
   - например: стоит ли предложить скидку / персональный контакт / апселл
   - интервенция должна быть явно указана пользователем или извлечена из запроса

Внутри PoC:

- получает профиль клиента и доступный контекст кейса;
- проверяет допустимые сценарии и ограничения;
- при необходимости повторно обращается к внутренним материалам / методичкам через RAG;
- запускает количественный инструмент оценки эффекта;
- формирует объяснимую рекомендацию с ограничениями и уровнем уверенности;
- отправляет кейс на ручной review, если данных недостаточно или уверенность низкая.

PoC не подбирает лучшую интервенцию из набора альтернатив. Аналитик должен задать конкретный сценарий для оценки.

## Что НЕ делает Proof of Concept

- автоматическое выполнение интервенции без подтверждения человека;
- полноценное обучение production-grade uplift-моделей на больших данных;
- поддержка всех возможных типов клиентов и интервенций;
- юридически значимые решения без human approval;
- полноценный online-learning loop;
- интеграция со всеми корпоративными системами в production-режиме.

## Почему это агентная система, а не просто чат с LLM

Система не просто получает большой контекст в prompt. Она:

- работает с несколькими внутренними источниками и инструментами;
- хранит состояние кейса и промежуточные результаты;
- использует отдельные не-LLM инструменты для оценки эффекта;
- реагирует на доступность источников: продолжает в degraded mode при частичных данных или прерывает кейс при полном отсутствии evidence;
- **запускает adaptive RAG retrieval** — при недостаточном контексте LLM формулирует уточнённый запрос и инициирует повторный поиск (LLM-driven control flow поверх rule-based safety);
- делает двухуровневый self-check: rule-based проверки + LLM-augmented смысловые проверки, с retry при выявленных проблемах;
- умеет отказываться от рекомендации и отправлять кейс на human review при слабом качестве данных.

Архитектурно это **гибридная агентность** (см. ADR-8 в `docs/system-design.md`): rule-based слои дают безопасность и предсказуемость, LLM-driven refinement loops дают реальный agentic pattern там, где он действительно нужен — в работе с retrieved-контекстом и смысловом self-check.

LLM в проекте отвечает за оркестрацию и объяснения, но не за вычисление эффекта и не за исполнение бизнес-правил.

## Тех. стек

- **Python 3.11** — основной язык
- **LangGraph** — оркестрация агента (поверх LangChain)
- **OpenAI API** (этап разработки) → собственные модели в контуре заказчика
- **FAISS + sentence-transformers** (`intfloat/multilingual-e5-small`) — RAG / retrieval
- **Streamlit** — UI для демо
- **Loguru** — структурированное логирование
